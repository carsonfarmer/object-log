# Spin single-repository authentication tranche

Issue #35, exclusive branch `cf/spin-git-auth`, based on `0a0d472`.

Spin defaults to fail-closed Basic authentication. The private parser accepts
configured 32-byte hexadecimal read/write tokens, rejects ambiguous config,
and decodes bounded Basic credentials using base64 0.22.1. Both subtle 2.6.1
constant-time comparisons execute before role decisions. Policy/auth validation
precedes storage opening and request-body consumption. HTTP/log failures contain
static categories; missing/invalid credentials challenge with 401, insufficient
scope returns 403, and unknown routes remain 404.

  368 ordinary tests passed, 16 opt-in ignored, Git WASIp2 and strict Spin
  all-target/all-feature WASIp2 checks passed.
- Locked release WASIp2 component build passed.
- `scripts/test-minio.sh auth_minio auth_minio object-log-git-spin ''`: both
  opt-in tests passed. Actual Spin rejects missing/wrong/malformed/duplicate/
  oversized credentials and invalid configuration with zero counting-backend
  calls. POST bodies are deliberately never sent: the response arrives before
  body consumption. Static response bodies, challenge, no Location, and secret
  absence from runtime output are checked for both hashes.
- Actual unchanged Git uses a real helper pipe and a mode-0600 random token file,
  verifies path scoping, writer push, reader clone/fetch and rejected push, cold
  restart with rotation, revoked read/write token failures, new-token operations,

## Fixture shutdown correction

A subsequent audit found that the Python helper stopped only `spin up`, which
can leave its HTTP child alive. Therefore the original cold/revocation run above
establishes new-host behavior but does not prove the old listener stopped.
The helper now starts an isolated process group, terminates that group, waits
for its parent, and checks that its listener closes before returning. Both-hash
actual HTTP preflight passes with this cleanup assertion. The full auth/MinIO
rotation run must be repeated with the corrected helper; it is currently blocked
by the shared Docker daemon being unavailable after local disk pressure. No
production authentication source changed for this fixture correction.

The stronger shutdown follow-up additionally waits for the entire private process
group to disappear using `killpg(pgid, 0)`, escalating from TERM to KILL at the
midpoint of a bounded deadline. Permission denial is treated as still live, never
as drained; listener closure requires connection refusal. A synthetic child that
never listens and ignores TERM proves KILL escalation and complete group drain.
The opt-in HTTP preflight gate now runs this control before the both-hash matrix;
that focused gate passed with strict fixture lint and Python syntax checks.
The coordinating task will rerun the full credential-helper lifecycle with this
final helper before accepting the corrected cold/revocation evidence.
