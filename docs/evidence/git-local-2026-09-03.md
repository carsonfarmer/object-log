# Local Git adapter qualification

## Result

At `72d148a30c1f1149a6a48097c638c39af157f805`, the Git adapter passed its
regular tests, request and byte audit, Criterion benchmark, and loopback MinIO
lifecycle. The lifecycle covers push, checkpoint, garbage collection, cache
deletion, cold recovery, and `git fsck --strict`.

The tests use the installed Git client to create input packs and check the
recovered repository. The product code does not run Git.

Publication does not read staged pack objects back. Checkpoint reads the tail
commit, pack node, and all pack blobs. Recovery reads the head, checkpoint,
pack node, and all pack blobs. The test asserts these exact request shapes.

## Loopback MinIO

Run:

```sh
make git-minio-test
```

The test uses the pinned image
`minio/minio@sha256:14cea493d9a34af32f524e538b8346cf79f3321eff8e708c1e2960462bd8936e`.
It creates a new bucket on an ephemeral loopback port. The test published a
live pack and a 1 MiB dead pack. It deleted the dead ref, published a
checkpoint, completed collection, opened a new log and cache, checked the
single live ref and file bytes, and ran `git fsck --strict`. The test binary
reported 0.82 seconds. The script removed its container.

## Limits

- These results measure one local process. They do not predict remote object
  store latency or throughput.
- MinIO checks S3 API compatibility on loopback. It does not qualify AWS S3.
- The benchmarks use SHA-1 packs. The regular suite covers SHA-1 and SHA-256.
- The benchmark timer excludes fixture creation. Publication includes pack
  normalization, object upload, commit write, and head publication.
- Checkpoint setup and cold-recovery object storage are warm in process memory.
- The recovered cache byte count includes Git index and repository metadata.
